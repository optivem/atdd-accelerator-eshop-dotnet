## Key Differences

### Lifecycle Management

| Aspect | ApiClient | UiClient |
|--------|-----------|----------|
| **State** | Stateless | Stateful |
| **Resource** | HttpClient (lightweight) | Browser + Page (heavy) |
| **Cleanup** | Not needed | Required via IAsyncDisposable |
| **Creation** | Per controller client | Once per test |

### Entry Point Pattern

| Aspect | ApiClient | UiClient |
|--------|-----------|----------|
| **Entry Point** | Direct controller instantiation | OpenHomePage() |
| **Navigation** | Not applicable | Via page hierarchy |
| **Pattern** | `new OrderControllerClient(baseUrl)` | `uiClient.OpenHomePage()` |

### Test Flow

#### API Test Flow
```csharp
// Direct instantiation
var orderClient = new OrderControllerClient(baseUrl);

// Direct action
var response = await orderClient.PlaceOrder(request);

// No cleanup needed
```

#### UI Test Flow
```csharp
// Create client (manages browser)
await using var uiClient = new UiClient(baseUrl);

// Navigate through hierarchy
var homePage = await uiClient.OpenHomePage();
var shopPage = await homePage.GoToShop();

// Perform actions
await shopPage.FillProductId("10");

// Automatic cleanup via using
```

## Responsibility Breakdown

### API Client Responsibilities

| Class | Responsibility |
|-------|----------------|
| **ApiClient** | HTTP communication (GET, POST, DELETE) |
| **OrderControllerClient** | Order-specific API endpoints |
| **EchoControllerClient** | Echo-specific API endpoints |

### UI Client Responsibilities

| Class | Responsibility |
|-------|----------------|
| **UiClient** | Browser lifecycle (create, manage, dispose) |
| **HomePage** | Navigation to other pages |
| **BasePage** | Common Playwright operations |
| **ShopPagePage** | Shop-specific UI interactions |
| **OrderHistoryPage** | Order history-specific UI interactions |

## Usage Examples

### API Test Example
```csharp
[Fact]
public async Task PlaceOrder_ShouldReturnOrderNumber()
{
    // Simple, direct instantiation
    var orderClient = new OrderControllerClient(TestConfiguration.BaseUrl);
    
    var request = new PlaceOrderRequest
    {
        ProductId = 10,
        Quantity = 5
    };
    
    // Direct method call
    var response = await orderClient.PlaceOrder(request);
    
    Assert.NotNull(response.OrderNumber);
}
```

### UI Test Example
```csharp
[Fact]
public async Task ShouldCalculateTotalOrderPrice()
{
    // Create client (manages browser lifecycle)
    await using var uiClient = new UiClient(TestConfiguration.BaseUrl);
    
    // Navigate through hierarchy
    var homePage = await uiClient.OpenHomePage();
    var shopPage = await homePage.GoToShop();
    
    // Perform actions
    await shopPage.FillProductId("10");
    await shopPage.FillQuantity("5");
    await shopPage.ClickPlaceOrder();
    
    var confirmationMessage = await shopPage.GetConfirmationMessage();
    var confirmation = shopPage.ParseConfirmationMessage(confirmationMessage);
    
    Assert.True(confirmation.TotalPrice > 0);
    
    // Browser automatically disposed
}
```

## Why Different Patterns?

### API: Lightweight, Stateless
- HTTP requests are fast and cheap
- No complex lifecycle to manage
- Direct instantiation is simple and clear

### UI: Heavy, Stateful
- Browser is expensive to create
- Page lifecycle needs management
- Navigation hierarchy mirrors user journey
- Proper cleanup is critical

## Summary

Both patterns achieve the same goal (test automation) but with different approaches suited to their domain:

| Aspect | API | UI |
|--------|-----|-----|
| **Complexity** | Low | High |
| **Lifecycle** | Simple | Complex |
| **Pattern** | Direct instantiation | Entry point + hierarchy |
| **State** | Stateless | Stateful |
| **Cleanup** | Not needed | Critical |
